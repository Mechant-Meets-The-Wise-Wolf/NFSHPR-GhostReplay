# 项目文件索引

更新时间：2026-10-23（0.1 首次构建，目录重组后）

这份文档回答三个问题：**哪些文件只在本机、哪些会进 GitHub、哪些会进发行包。** 不确定某个文件该怎么处理时，先查这里。

## 0. 现在的目录结构

根目录只放构建入口和说明；**可运行本体集中在 `app/`，进入该目录即可使用。**

```
HPRGhostReplay/
├─ Build.ps1                   主程序构建，默认输出 app\HPRGhostReplay.exe
├─ Package.ps1                 发行包生成，默认读取 app\HPRGhostReplay.exe
├─ VERSION                     版本号与产物哈希的唯一来源
├─ README.zh-CN.md             项目概览
├─ HANDOFF.zh-CN.md            开发交接
├─ app/                        可运行本体（进入即用）
│  ├─ HPRGhostReplay.exe       主程序
│  ├─ StartHPRGhost.cmd        启动入口，必须与 EXE 同级
│  └─ Recordings/              玩家录像与放置说明
├─ src/                        35 个 C# 源码
├─ data/                       events.tsv（473 赛事）、vehicles.tsv（132 车型）
├─ assets/                     图标源与设计说明
├─ licenses/                   格式许可与第三方声明
├─ native/                     原生工程：src、bin、vendor、Build.ps1
├─ packaging/                  打包源文档：使用说明、更新说明、第三方许可
├─ releases/                   发行 ZIP、SHA256、LATEST
├─ docs/                       文档、存档说明、本索引、需求记录
├─ tools/                      Verify-Archive.ps1
├─ research/                   历史证据（仅本地）
├─ archive/                    旧入口、迁移、清理、历史草稿
└─ source-share/               历史源码审阅包
```

程序的 `Recordings`、`Logs`、`GameFolder.txt` 都写在 EXE 所在目录，所以它们会落在 `app/` 内，不会污染项目根目录。

## 1. 三条规则

1. 要改程序、复现构建、看历史改动 → 看 **GitHub 仓库**。
2. 要查历史证据、旧版本、玩家录像 → 看 **本机目录**（git 忽略）。
3. 要发给玩家 → 看 **`releases/` 里的 ZIP**（仓库内容的子集）。

三者是逐层收窄，不是三份不同的代码。机制细节见 [版本与产物.md](版本与产物.md)。

## 7. 自己核对的方法

```bash
git ls-files                     # 仓库到底收了哪些文件
git status --ignored --short     # 哪些被忽略、哪些未提交
git check-ignore -v research/    # 某个路径为什么没入库
```

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Verify-Archive.ps1
```

最后一条会核对 `app/HPRGhostReplay.exe`、ASI、加载器、ZIP 与 ZIP 内 EXE 是否都符合 `VERSION`。

## 8. 最容易看懵的四组

1. **`app/` 与桌面版**：`app/` 是项目内的可运行副本，桌面的 `HPRGhostReplay` 是日常使用实例。两者录像库和配置完全独立。
2. **`packaging/` 与 `releases/`**：前者是打包用的源文档，后者是生成的发行包。以前叫 `release/`，容易和 `releases/` 看混，所以改了名。
3. **`src/` 与 `research/before-*`**：`src/` 是活动源码，`research/before-*` 是历史快照，里面的同名文件不要当现行版本。
4. **两份 156,526 字节的录像**：`01分26秒87` 和 `01分26秒91` 是不同场次，大小相同是巧合，不是重复文件。

## 9. 备份建议

| 目标 | 备份什么 | 体积 |
| --- | --- | --- |
| 只保代码与成品 | 整个 git 仓库（含 `.git`） | 约 8 MB |
| 保完整项目 | 整个目录，含 `research/` 与 `app/Recordings/` | 约 591 MB |
| 保历史证据与录像 | `research/`、`app/Recordings/`、`archive/` | 约 581 MB |

只备份 GitHub 仓库会丢掉研究证据和玩家录像；只备份本机目录则没有版本历史。两者互补，不要只留一份。
